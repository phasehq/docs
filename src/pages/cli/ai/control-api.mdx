# Phase AI control API

The Phase AI proxy serves a small HTTP API at the reserved host `http://phase.invalid`. Agents running behind the proxy use it to see which Connections they can use, discover what Phase can manage, and ask a human for a new or updated Integration credential. {{ className: 'lead' }}

<Note>
This is not the [Phase public API](/public-api). It is served locally by the CLI's Phase AI proxy (`phase ai run`, `phase ai exec`, the background proxy that `phase ai enable` sets up, or a [relay](/cli/ai/relay)), only to processes running inside a Phase AI session. It is not reachable from anywhere else, and it does not accept Phase tokens.
</Note>

<DocActions />

## Reaching the API

`phase.invalid` never resolves in DNS. A request only reaches the API through the Phase AI proxy, which answers it itself before any upstream connection is made.

Inside a Phase AI session the proxy settings are already in the environment (`HTTP_PROXY` and `HTTPS_PROXY`), so any HTTP client that honours them works:

```bash
curl --fail --silent --show-error http://phase.invalid/v1/status
```

| | |
| --- | --- |
| Base URL | `http://phase.invalid` (plain `http`; the proxy answers it locally) |
| Authentication | `Proxy-Authorization: Basic base64("phase:<capability>")`. The capability is the per-process proxy password in the session's proxy URL. It is never a Phase token. |
| Connection scope | The proxy username `phase.<connectionId>` instead of `phase` scopes a request to one Connection. |
| Format | JSON request and response bodies. Every response is sent with `Cache-Control: no-store`. |
| Query strings | Rejected with `400 invalid_control_query`, except `wait` on request creation and polling, and `serviceType` on context. |
| Browsers | A `POST` that carries `Origin`, `Referer`, or a `Sec-Fetch-Site` header other than `none` is refused with `403 browser_control_mutation_rejected`. |
| Limits | Request bodies up to 64 KiB. IDs match `^[A-Za-z0-9._-]{1,128}$`. `markdown` up to 16 KiB. `wait` is 0 to 300 whole seconds. Unknown JSON fields are rejected. |

A missing or wrong capability is refused before any route runs:

```text
HTTP/1.1 407 Proxy Authentication Required
Proxy-Authenticate: Basic realm="Phase Agent session"
X-Phase-Error-Code: invalid_runtime_capability
Content-Type: application/json

{"error":{"code":"invalid_runtime_capability","message":"A valid Phase AI runtime capability is required.","retryable":false,"details":{}}}
```

### Local proxy and relay

A [relay](/cli/ai/relay) serves the same API over its TLS proxy, with these differences:

| Route | Local proxy | Relay |
| --- | --- | --- |
| `GET /v1/bootstrap` | Not available | Available |
| `GET /v1/discover` | Available | Not available |
| `POST /v1/rotate` | Available | Not available |
| `POST /v1/revoke` | Available | Not available |

Every other route is available on both. An unknown or unavailable route returns `404 control_route_not_found`.

## Errors

Every error uses the same envelope and also sets the `X-Phase-Error-Code` header:

```json
{
  "error": {
    "code": "invalid_control_request",
    "message": "Use setup with serviceType or credential_update with connectionId and credentialId. credentialProvider, credentialName, markdown, and an optional dedupKey are required.",
    "retryable": false,
    "details": {}
  }
}
```

When Phase Console rejects a call, the proxy passes Console's status, code and message through. If Console can't be reached, the proxy returns `502 agent_control_relay_failed` with `retryable: true`.

| Code | Status | Meaning |
| --- | --- | --- |
| `invalid_runtime_capability` | 407 | The proxy capability is missing or wrong. |
| `invalid_control_query` | 400 | The route does not accept a query string. |
| `invalid_control_wait` | 400 | `wait` is not a whole number from 0 to 300. |
| `invalid_control_request` | 400 | The request body is not a valid request. |
| `invalid_control_content_type` | 415 | The body is not `application/json`. |
| `browser_control_mutation_rejected` | 403 | A browser sent the `POST`. |
| `control_route_not_found` | 404 | No such route on this proxy. |
| `agent_session_unavailable` | 503 | The session is refreshing or unavailable. Retry shortly. |
| `agent_control_relay_failed` | 502 | Phase Console could not complete the call. Retryable. |
| `approved_request_refresh_failed` | 502 | A request was approved, but the proxy could not apply the new configuration safely. Wait until status shows the Connection as `ready`. |

## Requests

When no suitable Connection exists, or a provider rejects the current credential, an Agent asks a human through a request. The human reviews it in Phase Console at the request's `approvalUrl`, creates or picks the Integration credential, and approves or denies it.

There are two kinds:

- **`setup`** asks for a new Integration credential and Connection for a service.
- **`credential_update`** asks for a change to the credential behind an existing Connection, for example a missing permission or an expired key.

A request is `pending` until a human acts. It ends as `approved`, `denied`, `cancelled`, or `expired`; pending requests expire after 7 days. A Workflow can have at most 20 pending requests (`429 pending_request_limit`).

### Runtime action

An approved request tells the runtime what the approval changed:

| `runtimeAction` | Meaning | What to do |
| --- | --- | --- |
| `retry` | The proxy already applied the change without changing what the Agent's processes see. | Retry the operation. |
| `restart_required` | Decoys, identifiers, routes or the process environment changed. | The background proxy that `phase ai enable` set up recycles its session on its own, and the next command picks up the change. Relaunch `phase ai run`. |

An approved `setup` normally returns `restart_required`. An approved `credential_update` returns `retry` unless the change affected what processes see.

## Session routes

These routes manage the proxy's session. Agents don't need them; they are used by the CLI and by tooling.

| Route | Available | What it does |
| --- | --- | --- |
| `POST /v1/refresh` | Local and relay | Re-reads the Workflow's configuration from Console now. Body empty or `{}`. Agents should not call it. |
| `POST /v1/rotate` | Local only | Rotates the proxy's session credential with Console. No body. The proxy capability does not change. |
| `POST /v1/revoke` | Local only | Revokes the session in Console and stops the proxy. No body. `phase ai disable` uses it. |
| `GET /v1/discover` | Local only | The Console configuration for this session: Connections, hosts and bindings, never live credentials. For diagnostics. |

The proxy also serves its full runtime manifest at `GET /.well-known/agents`. The CLI reads it to build a managed command's environment. It contains the proxy password, decoys and the CA certificate, so Agents must not fetch, print or store it; use [status](#get-status) instead.

## Proxied traffic

Everything not sent to `phase.invalid` is ordinary proxied traffic. Requests to hosts bound to one of the Workflow's Connections are intercepted, checked, and sent upstream with the live credential in place of the decoy. Other hosts pass through untouched, unless the proxy runs with `--lockdown`, which blocks them.

Every response to bound traffic, and every refusal, carries an `X-Phase-Event-Id` header with the ID of the event the proxy reported to Console for that request. It contains no credential material. Quote it when reporting a problem so the human can find the request in Console. AWS-style error responses repeat it as `RequestId`. Pass-through traffic has no event and no header.

Failures on bound traffic use the error envelope above, except for AWS Connections, which return an AWS-style XML error. Failures tied to a Connection also set `X-Phase-Connection-Id` and `X-Phase-Grant-Id`.

| Code | Status | Meaning |
| --- | --- | --- |
| `agent_connection_denied` | 403 | The Connection is not authorized for this request. |
| `credential_minting_blocked` | 403 | The call would mint new credentials (for example `sts:GetSessionToken` or `iam:CreateAccessKey`), which the proxy never allows. |
| `agent_credential_injection_failed` | 403 | The live credential could not be injected, for example because the request was not signed with the decoy. |
| `ambiguous_agent_binding` | 403 | Several Connections match and none was selected. Use `phase ai exec --connection`. |
| `unbound_host_blocked` | 403 | The host is not bound to the Workflow and the proxy runs with `--lockdown`. |
| `agent_binding_unavailable` | 503 | The session is recycling. Retry shortly. |
| `upstream_unavailable` | 502 | The upstream service could not be reached. |
